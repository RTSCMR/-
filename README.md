# ألف

سوق سعودي يربط المتاجر الصغيرة بصنّاع المحتوى. التاجر يحدد سعر كل ألف مشاهدة، صانع المحتوى ينشر، والمحاسبة على المشاهدات المعتمدة فقط.

## التشغيل

```bash
npm install
cp .env.example .env      # غيّر ADMIN_PASSWORD
npm run setup             # ينشئ قاعدة البيانات + حساب المشرف + بيانات تجريبية
npm run dev               # http://localhost:3000
```

بدون بيانات تجريبية: `npm run db:push && npm run db:seed`.

للإنتاج: `npm run build && npm start`.

| الحساب | الإيميل | كلمة المرور |
|---|---|---|
| المشرف | قيمة `ADMIN_EMAIL` (الافتراضي `admin@alf.sa`) | قيمة `ADMIN_PASSWORD` |
| تاجر تجريبي | `merchant@demo.alf` | `demo12345` |
| صنّاع تجريبيين | `creator@demo.alf`، `creator2@demo.alf`، `creator3@demo.alf` | `demo12345` |

أول شي يسويه المشرف: يضيف الحساب البنكي من **الإعدادات**، لأن التاجر يشوفه في صفحة تحويل العربون.

اختبارات الحساب المالي: `npm test`.

## التقنية

- Next.js 16 (App Router) + TypeScript + Tailwind 4
- Prisma 6 + SQLite
- كل التعديلات عبر Server Actions في `src/lib/actions.ts`، وكل إجراء يتحقق من الدور والملكية بنفسه
- الخطوط محمّلة محلياً من `@fontsource` (بدون طلبات لقوقل)

## دورة الحملة

```
الحملة:    بانتظار العربون → العربون قيد التأكيد → مفتوحة للتقديم → التقديم مقفل → بانتظار التسوية → مسوّاة
                (التاجر يبلّغ)      (المشرف يأكد)     (يدوي أو بانتهاء المدة)  (تلقائي)      (المشرف يسجّل)

المشاركة:  طلب جديد → مقبول → المسودة عند التاجر ⇄ مطلوب تعديل → المسودة معتمدة → منشور
           → المشاهدات قيد المراجعة ⇄ مرفوضة → معتمد بانتظار التحويل → تم التحويل
```

كل انتقال ينكتب في جدول `Event` (من، إلى، مين، متى، ملاحظة) ويظهر في «السجل الزمني» داخل صفحة الحملة والمشاركة. الانتقال مشروط بالحالة الحالية داخل transaction، فلو ضغط اثنين نفس الزر ما يتكرر الإجراء.

## القرارات اللي أخذتها

**المال**

- المبالغ تتخزن بالهللة كأعداد صحيحة. كل المعادلات في `src/lib/money.ts` ولها اختبارات.
- **العمولة تنخصم من مستحق الصانع، مو تنضاف على التاجر.** التاجر يدفع `المشاهدات ÷ 1000 × سعر الألف` بالضبط، والصانع يستلم هذا المبلغ ناقص العمولة. كذا سعر الألف اللي يكتبه التاجر هو فعلاً اللي يدفعه.
- **حصة الصانع من السقف = سقف الميزانية ÷ عدد الصنّاع المطلوبين.** التاجر يحدد العدد وقت الإنشاء (1 إلى 20)، وما ينقبل أكثر منه. بهالطريقة مجموع المستحقات مستحيل يتجاوز السقف.
- نسب العربون والعمولة **تتثبّت على الحملة وقت إنشائها**. لو غيّر المشرف الإعدادات، الحملات القائمة ما تتأثر.
- لو المستحق النهائي طلع أقل من العربون، الفرق يتسجل كمسترد للتاجر.
- المشرف يقدر يعتمد عدد مشاهدات غير اللي أدخله الصانع (مثلاً لو جزء منها مو من السعودية).

**الدورة**

- «مدة الحملة» = فترة استقبال الطلبات بعد النشر. لما تنتهي ينقفل التقديم تلقائياً والطلبات المعلّقة تنرفض، والمقبولين يكمّلون شغلهم.
- الحملة تنتقل لـ«بانتظار التسوية» تلقائياً لما ينقفل التقديم وتكتمل كل المشاركات.
- مدة الانتظار قبل إدخال المشاهدات (7 أيام) قابلة للتعديل من إعدادات المشرف. مفيدة للتجربة: حطها 0.
- التاجر يقدر يلغي الحملة قبل ما يبلّغ بالتحويل فقط. بعد تأكيد العربون ما فيه إلغاء، فيه قفل تقديم.
- المشرف يقدر يلغي مشاركة متعثرة (صانع اختفى مثلاً) عشان ما تعلّق الحملة.
- تحويل مستحق الصانع ما ينتظر تسوية التاجر. المشرف يقرر، والصفحة تنبهه.
- قفل الحملات المنتهية يصير عند فتح أي لوحة تحكم (بدون cron). يكفي للبداية.

**الحسابات والأمان**

- كلمات المرور bcrypt (cost 12). الجلسة رمز عشوائي في كوكي `httpOnly` / `sameSite=lax` (و`secure` في الإنتاج)، وقاعدة البيانات تحفظ بصمته SHA-256 فقط. مدتها 30 يوم.
- حد لمحاولات الدخول: 8 محاولات كل ربع ساعة لكل إيميل، في الذاكرة.
- **التنبيهات** ما لها جدول مستقل: هي أحداث السجل الزمني اللي تخص المستخدم وسوّاها غيره، وعدّاد الجديد يعتمد على آخر مرة فتح فيها الصفحة.
- **استرجاع كلمة المرور**: رابط لمرة واحدة صالح 24 ساعة، تنحفظ بصمته فقط، واستخدامه يطلّع المستخدم من كل الأجهزة. وأي مستخدم يقدر يغيّر كلمته من صفحة حسابه.
- ما فيه تسجيل كمشرف. المشرف ينشأ من `db:seed` فقط.
- لقطات الإحصائيات تنحفظ في `uploads/` خارج `public`، وتنعرض عبر `/api/uploads/...` للمشرف وصاحب المشاركة وتاجر الحملة فقط. النوع يتحقق منه من محتوى الملف (PNG / JPG / WebP، حد 5 ميجا).
- الملف العام للصانع (`/creators/[id]`) ما يعرض إيميل ولا جوال ولا آيبان.

**الهوية**

- الاسم والشعار: كلمة «ألف» وبعدها ثلاث معيّنات حمراء، هي أصفار الألف الثلاثة (الصفر العربي ٠ نقطة معيّنة).
- لون واحد: جمري `#D7331A`، على ورق دافئ `#F2EDE2` وحبر `#17130E`. بدون تدرجات ولا ظلال ولا زجاجي، وزوايا شبه حادة.
- اللون الأساسي له معنى واحد في اللوحات: **رقم مهم أو شي ينتظر منك إجراء**. الشارات: حمراء = يحتاج إجراء، منقّطة = بانتظار طرف ثاني، سوداء = مكتمل.
- العناوين والأرقام بخط Lalezar، والنصوص بخط IBM Plex Sans Arabic.
- الأرقام لاتينية (1,000) لأنها الأوضح في المبالغ، وتنقبل الأرقام العربية في الإدخال.
- عنصرين متكررين من فكرة العدّ: مسطرة التدريج، وسطور الفاتورة المنقّطة (البند ..... المبلغ).
- التنقل على الجوال شريط سفلي ثابت، بنص بدون أيقونات.

## اللي ما انبنى (عن قصد)

- **بوابة دفع**: المنصة تسجّل حالة التحويلات فقط.
- **إشعارات إيميل أو جوال**: البديل صفحة «التنبيهات» داخل المنصة مع عدّاد للجديد.
- **استرجاع كلمة المرور بالإيميل**: البديل إن المشرف ينشئ رابط استرجاع من صفحة «المستخدمين» ويرسله بنفسه.
- **التحقق الآلي من المشاهدات**: المراجعة يدوية من لقطة الشاشة.

## التحويل إلى Postgres

1. في `prisma/schema.prisma` غيّر `provider = "sqlite"` إلى `"postgresql"`.
2. غيّر `DATABASE_URL`.
3. `npx prisma migrate dev`.

المخطط ما يستخدم شي خاص بـ SQLite. الحالات نصوص (معرّفة في `src/lib/status.ts`) وتقدر تحولها لـ enum بعدين.

قبل النشر على أكثر من خادم: انقل `uploads/` لتخزين سحابي، وحد محاولات الدخول لـ Redis أو ما يشابهه.
